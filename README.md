# المصطفى — لوحة إدارة الفريق

تطبيق ويب عربي للمالك والمدير، مبني باستخدام Next.js 16 وReact وTailwind CSS وSupabase. يدعم RTL والشاشات الصغيرة والمظهر الداكن. يستخدم خط Noto Sans Arabic بملفات محلية وأحجام أوضح للنصوص، ولا يحتاج طلبات إلى Google Fonts.

## التشغيل

```sh
npm install
npm run dev
```

- الدخول الحقيقي: http://localhost:3000
- تجربة مستقلة ببيانات محلية: http://localhost:3000/demo
- حساب المالك يُجهّز باستخدام البريد الذي يحدده مسؤول المشروع، ولا تُحفظ بيانات الدخول في المستودع.
- مفاتيح الاتصال المحلية محفوظة في `.env.local` وهو مستبعد من Git. لا تُرفع مفاتيح الخادم إلى المستودع أو إلى متغير يبدأ بـ `NEXT_PUBLIC_`.

## الميزات المنفذة

- دخول بالبريد وكلمة المرور، والتحقق من الجلسة والصلاحية في كل طلب للخادم.
- لوحة إحصائيات، فصل الدوام عن وقت العمل الفعلي، ونسبة الدوام الشهرية.
- إضافة الموظفين وتعديل بياناتهم وإسناد ساعات العمل اليومية.
- **حذف نهائي بدل الأرشفة، حسب التعديل المعتمد.** يعرض تأكيدًا واضحًا، ويحذف الموظف ومهامه ودوامه وتقاريره وطلبات المراجعة المرتبطة به. يُلغى وصول حسابه في نفس معاملة قاعدة البيانات، ثم يُحذف سجل Supabase Auth. تعذّر تنظيف سجل Auth لا يعيد صلاحية الحساب.
- لوحة مهام بثلاث حالات مع عرض قائمة، بحث وتصفية، أولوية وموعد، وسجل نشاط.
- حذف المهام للمالك والمدير من البطاقة والقائمة والتفاصيل بعد التأكيد. تُحذف أنشطة المهمة وطلبات مراجعتها وسجلات إشعاراتها، وتبقى سجلات الدوام والتقارير.
- زر الوضع المظلم أعلى الواجهة وعلى شاشة الدخول والتفعيل، مع حفظ الاختيار ومزامنته بين تبويبات المتصفح.
- نقطة حمراء على الجرس للإشعارات غير المقروءة، وتنبيه منبثق لمدة 5 ثوانٍ عند إسناد مهمة أو تغيير حالتها أو طلب مراجعتها. تتضمن قائمة الجرس زر «تحديد الكل كمقروء»، مع حفظ الحالة لكل حساب. لا تتكرر التنبيهات القديمة عند تحديث الصفحة.
- أرقام الواجهة والإحصائيات والتواريخ بالإنجليزية، مع بقاء اللغة وأسماء الأشهر عربية.
- عرض التقارير اليومية وتفاصيل الموظف والمهام المكتملة، وتصدير CSV يدعم العربية ويمنع صيغ الجداول في القيم المدخلة.
- إدارة أيام العمل واسم المؤسسة والحسابات والأدوار من المالك.
- توكن تلكرام مشفر بـ AES-256-GCM ومحفوظ في جدول لا يقرأه المتصفح؛ إرسال الإشعارات من Route Handlers مع مهلة محددة وسجل تسليم.
- تحديثات Realtime للبيانات المشتركة مع إعادة مزامنة احتياطية كل دقيقة.
- مسارات جاهزة لتكامل تطبيق الدسكتوب، موضحة في `docs/DESKTOP-API.md`.

## الصلاحيات

| الدور | الصلاحيات |
| --- | --- |
| المالك | إدارة كاملة، تعديل بيانات الموظفين، الإعدادات، إنشاء الحسابات وتغيير أدوارها |
| المدير | الإحصائيات والتقارير وإضافة الموظفين وحذف الموظفين العاديين وإسناد المهام |
| الموظف | الدسكتوب فقط، قراءة بياناته، تغيير حالة مهامه، تسجيل دوامه وتقاريره وطلب المراجعة |

المدير لا يستطيع تعديل بيانات موظف قائم، حسب القراءة المحافظة لجدول الصلاحيات في الوثيقة. لا يمكن حذف حساب المالك أو الحساب الذي ينفذ الحذف. حذف مدير آخر متاح للمالك فقط. لا توجد صفحة تسجيل عام، والحساب الذي ليس له ملف صلاحيات لا يستطيع استعمال التطبيق.

## قاعدة البيانات

يُحدد مشروع Supabase عبر متغيرات البيئة المحلية أو إعدادات منصة الاستضافة.

طُبّقت الملفات التالية بالترتيب على المشروع الحالي:

1. `supabase/migrations/001_initial.sql`
2. `supabase/migrations/002_guards.sql`
3. `supabase/migrations/003_employee_deletion.sql`
4. `supabase/migrations/004_task_deletion.sql`
5. `supabase/migrations/005_review_notifications.sql`

لا تُعد تشغيل ملفات الإنشاء على المشروع نفسه. على مشروع جديد، شغّلها بالترتيب في SQL Editor، أو استخدم آلية migrations الخاصة بـ Supabase. جميع جداول التطبيق لديها RLS مفعّل؛ الجداول الحساسة محجوبة عن `anon` و`authenticated`.

انسخ `.env.example` إلى `.env.local` واملأ القيم على جهازك فقط. ملف المثال يحتوي أسماء المتغيرات دون قيم حقيقية، وملفات البيئة المحلية مستبعدة من Git. يجب إبقاء `BOT_ENCRYPTION_KEY` ثابتًا عند النشر، وإلا لن يمكن فك التوكن المحفوظ. متغيرات `NEXT_PUBLIC_` مخصصة للمتصفح؛ مفتاح الخدمة ومفتاح التشفير للخادم فقط.

## قواعد الحساب

- المنطقة الزمنية: بغداد `Asia/Baghdad`.
- المطلوب الشهري: ساعات الموظف اليومية × أيام العمل من تاريخ انضمامه إلى آخر يوم انقضى ضمن الشهر، مع احتساب اليوم الحالي.
- أيام العمل الافتراضية: الأحد إلى الخميس؛ يمكن للمالك تغييرها.
- نسبة الدوام تعتمد على الدوام الشامل للخمول. وقت العمل مقياس مستقل، وقد تتجاوز نسبة الدوام 100% عند العمل الإضافي.
- يتم استخدام جدول العمل والساعات اليومية **الحاليين** عند حساب الأشهر السابقة؛ الإجازات والاستثناءات وتاريخ تغييرات جدول العمل غير ممثلة في هذه النسخة.
- الدسكتوب يرسل ثواني الدوام والعمل التراكمية لكل جلسة ويقسم الجلسة عند منتصف الليل المحلي. لا توجد مراقبة نشاط متصفح الموظف.
- قراءات القوائم مقسمة إلى دفعات لتفادي حد Supabase الافتراضي. توجد حماية توقف القراءة مع خطأ عند تجاوز 100 ألف سجل في جدول، بدل عرض إحصائيات ناقصة بصمت. للاستخدام الكبير، انتقل إلى تجميع الإحصائيات في قاعدة البيانات وتصفية الخادم بحسب الفترة.

## التحقق

```sh
npm run test
npm run typecheck
npm run build
npm run check:secrets
```

توجد 9 اختبارات لحساب الدوام والمنطقة الزمنية والتحقق من المدخلات. ويمكن تشغيل `node scripts/integration-test.mjs` مع خادم محلي متصل، لكنه ينشئ حسابات وبيانات مؤقتة في مشروع Supabase المحدد ويزيلها في النهاية. لا يشغّل إرسال رسائل أو يغير إعداد البوت. يختبر عزل البيانات ومنع ترقية الصلاحية وإسناد المهام وتغيير الحالة والدوام والتقارير والحذف النهائي.

فحص `check:secrets` يراجع محتوى الملفات المجهزة في Git ويمنع وجود قيم `.env.local` أو أنماط مفاتيح معروفة، دون طباعة القيم نفسها. شغّله بعد `git add` وقبل كل رفع.

## النشر على Vercel

1. ارفع الكود إلى مستودع خاص واستورده في Vercel كمشروع Next.js.
2. أضف قيم المتغيرات الأربعة من `.env.local` إلى بيئة Vercel. اجعل مفاتيح الخادم سرية، واحتفظ بمفتاح التشفير نفسه.
3. انشر المشروع، وأضف عنوانه إلى Site URL وRedirect URLs في إعدادات Supabase Auth.
4. استخدم عنوان الإنتاج كأساس لمسارات الدسكتوب.
5. سجّل الدخول بحساب المالك وأدخل توكن البوت من الإعدادات. يجب أن يبدأ كل موظف محادثة مع البوت وأن يُسجَّل Telegram ID الرقمي الخاص به.

النشر العام على Vercel لم يُنفّذ بعد. التطبيق الحالي يعمل محليًا، وقاعدة البيانات حقيقية. تطبيق الدسكتوب نفسه خارج ملفات هذا المشروع، ويحتاج توصيله بعقد التكامل قبل ظهور دوام وتقارير حقيقية.
